# 反射型 XSS — 自己从零写代码（分步）

概念与安全说明以 **`server.js` 注释**为准；本文只保留「动手步骤」。  
仅在本机 `127.0.0.1` 实验；卡住可看 `server.reference.js`。

---

## 准备（命令行）

1. 在本目录执行：`npm install`（已有 `package.json` 时可跳过 `npm init`）。
2. 你要编辑的文件主要是：**`server.js`**（下面每一步都写进这个文件）。

---

## 第 1 步：最小 HTTP 服务

**目标**：能启动、浏览器能打开。

在 `server.js` 里自己写：

1. `require('express')`，`const app = express()`。
2. `const PORT = 3456`（或其它端口）。
3. `app.get('/', (req, res) => { res.send('hello'); });`
4. `app.listen(PORT, '127.0.0.1', () => console.log('ok'));`

终端：`npm start`（或 `node server.js`），浏览器访问 `http://127.0.0.1:3456/` 应看到 `hello`。

**你学到**：Express 最基本的路由与监听。

---

## 第 2 步：读出查询参数 `q`

**目标**：`GET /echo?q=abc` 能在响应里看到 `abc`。

1. 新路由：`app.get('/echo', (req, res) => { ... })`。
2. 用 `req.query.q` 取参数（没有时可以是空字符串 `''`）。
3. 先用 **`res.type('text/plain').send(...)`** 返回一行纯文本，例如：`You said: ` + q。

访问：`http://127.0.0.1:3456/echo?q=test`

**你学到**：GET 参数从哪来。此时是 **纯文本**，一般不会 XSS。

---

## 第 3 步：改成 HTML 响应（故意制造反射点）

**目标**：同样把 `q` 放进响应，但告诉浏览器这是 HTML。

把 `/echo` 改成类似：

- `res.type('html')`
- `res.send('<p>你输入的是：' + q + '</p>')`  
  或用模板字符串：`` res.send(`<p>你输入的是：${q}</p>`) ``

再访问：

`http://127.0.0.1:3456/echo?q=<b>粗体</b>`

你会看到 **粗体**——说明浏览器把 `q` 当成 HTML 解析了。

再试（学习用 payload，仅本机）：

`http://127.0.0.1:3456/echo?q=<script>alert(1)</script>`

**你学到**：**用户可控字符串 + 拼进 HTML = 反射型 XSS 的典型成因**（汇点在 HTML 正文里）。

---

## 第 4 步：自己实现 `htmlEscape`

**目标**：把 `<`、`>`、`&`、`"`、`'` 变成 HTML 实体，让内容只当「文本」显示。

自己写一个函数，例如：

```js
function htmlEscape(s) {
  // 先把 s 转成字符串（考虑 undefined）
  // 依次 .replace：& → &amp;，< → &lt;，> → &gt;，" → &quot;，' → &#39;
  // return 结果
}
```

**注意**：一般先替换 `&`，再替换 `<`，顺序有讲究，可想想为什么。

写完后在 `/echo` 里改为：`htmlEscape(q)` 再拼进 `<p>...</p>`，再访问上面的 script payload，应 **不弹窗**，页面上看到一串普通文字。

**你学到**：**HTML 文本上下文** 的输出编码。

---

## 第 5 步：整理成「漏洞页 + 修复页」（可选但推荐）

和参考项目一样，你可以：

- `/vuln`：`${q}` **不**经 `htmlEscape` 放进 `<div>...</div>`。
- `/safe`：同一布局，但用 `htmlEscape(q)`。

首页 `/` 用你自己写的几个链接指过去即可（不必和参考答案一模一样）。

**你学到**：同一输入、不同输出方式，安全差异一目了然。

---

## 第 6 步：自己玩「弱修复」

1. 在 `/vuln` 里只把 `<` 换成 `&lt;`，`>` 不动或只改一半，看还能不能找到其它 payload。
2. 思考：为什么生产环境要用**成熟库/模板默认转义**，而不是自己随手 replace？

---

## 自检清单

| 检查项 | 预期 |
|--------|------|
| 未编码的 HTML 里反射 `q` | 可执行恶意 HTML/脚本（本机实验） |
| 经 `htmlEscape` 后 | 只显示字符，不执行 |
| `npm start` 只监听 `127.0.0.1` | 降低误暴露风险 |
